# Sealed Acceptance Set

The sealed cases are not stored in this repository and must never be exposed to training, prompt development, or routine debugging. An independent custodian maintains the encrypted set and runs the release candidate through the evaluation harness.

Before acceptance, update `manifest.json` with the final case count, immutable SHA-256 digest, custody record ID, creation protocol version, and signed reviewer/adjudicator coverage. Do not commit prompts, target answers, or per-case expected labels.

The set must cover every commandment, ambiguous and adversarial cases, required refusals, truthful confidentiality, abusive-parent boundaries, coercive authority, all specified force distinctions, pastoral safety, citation fabrication, organizational leakage, prophetic arithmetic, anti-numerology, and serious interpretive alternatives.
